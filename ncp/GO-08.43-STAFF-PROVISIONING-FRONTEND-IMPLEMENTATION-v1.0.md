## 1. Scope

The frontend implementation for **Staff Provisioning v1.0** has been fully executed according to the ratified specifications in `GO-08.41` and `GO-08.42`.

The implementation delivers:
- **`SCR-14` (`StaffDirectoryScreen`):** Full-featured team roster and pending invitations management cockpit.

- **`SCR-15` (`InvitationAcceptanceScreen`):** Public responsive screen for inspecting and claiming staff invitations (existing user login or new user account provisioning).
- **Data & Client Layer:** `SaasStaffModel` DTOs and `SaasStaffService` consuming all 10 REST endpoints.

## 4. Reused Components & Infrastructure

The implementation maximized reuse of existing core SaaS infrastructure:
- **`ApiService`:** Automatic injection of `Authorization: Bearer <jwt>` and `x-active-membership-id` headers on `/api/saas/*`.
- **`ActiveContextHolder`:** Direct in-memory active context inspection and post-acceptance context loading.
- **`AuthService`:** Leveraged for existing user login and new user session initialization (`OBS-01`).
- **`AvailableContextSelectorScreen` (`SCR-04`):** Linked from missing active context state guards.
- **Design System Patterns:** Consistent use of badges (`_buildRoleBadge`, `_buildStatusBadge`), shimmers, modal dialogs, and responsive flex containers.

---

## 5. SCR-14: StaffDirectoryScreen Implementation

- **Dual-Tab Architecture:**
  - **Tab 1 (Personal):** Renders all current team members with role badges, status chips, relation types, and action buttons. Search field debounces queries across name/email. Dropdowns filter by role and lifecycle status.
  - **Tab 2 (Invitaciones Pendientes):** Lists unaccepted invitations, days remaining until expiry, and triggers for **Reenviar** (+7 days renewal) and **Cancelar** (revocation).
- **Active Context Guard:** If `hasActiveContext == false`, displays `_buildMissingContextState()` with direct CTA to `SCR-04`.

---

## 6. SCR-14 Modules Implementation

- **`SCR-14-M1` (`StaffInviteModal`):**
  - Text input for email with RFC-5322 validation.
  - Role dropdown dynamically conditioned by actor role (`MANAGER` is strictly locked to `PROFESSIONAL`/`RECEPTIONIST`).
  - Relation type dropdown editable for `OWNER` and locked to default for `MANAGER`.
  - On emission success: Displays green card with copyable invitation URL and auto-switches to pending tab.
- **`SCR-14-M2` (`StaffRoleDialog`):**
  - Displays current role and available target roles.
  - Enforces self-mutation guard (`member.userId == currentUserId` disables submit and renders warning banner).
  - Handles `422 CANNOT_ORPHAN_ESTABLISHMENT` error cleanly.
- **`SCR-14-M3` (`StaffStatusDialog`):**
  - Segmented control to Suspend, Reactivate, or Revoke.
  - Details operational retention implications (0 availability slots, preserved past tickets/appointments).
  - Enforces typing `"CONFIRMAR"` for permanent Revocation.
- **`SCR-14-M4` (`StaffRelationTypeDialog`):**
  - Owner-exclusive dialog to switch between `STAFF_EMPLOYEE`, `INDEPENDENT_PROVIDER`, and `OWNER_PARTNER`.

---

## 7. SCR-15: InvitationAcceptanceScreen Implementation

- **Token Inspection:** Calls `GET /api/saas/public/invitations/:token`. If expired/revoked/invalid, displays structured error card with retry CTA.
- **Existing User Path:** If `user_exists == true`, presents single-click confirmation *"Aceptar y Unirme al Salón"* calling `acceptInvitation`.
- **New User Path:** If `user_exists == false`, presents streamlined account creation form (`full_name`, `password`, `confirm_password`). On submit, claims invitation and initializes session via `AuthService.login` (`OBS-01`).
- **Post-Acceptance Forwarding:** Loads the new `membership_id` into `ActiveContextHolder` and navigates to `HubSalonScreen`.

## 8. Identity & Tenancy Invariants

Strict enforcement of:
$$\text{PERSON} \neq \text{USER} \neq \text{ACCOUNT} \neq \text{MEMBERSHIP} \neq \text{CUSTOMER}$$

- Zero customer table (`saas_customers`) manipulation.
- Salon managers/owners never view or manipulate staff passwords.
- Multiple memberships across establishments remain cleanly separated under `x-active-membership-id`.

## 9. Active Context Integration

- No client-supplied `tenant_id` or `establishment_id` in request payloads.
- All requests delegate to `ApiService`, which injects `x-active-membership-id` from `ActiveContextHolder().activeMembershipId`.

## 12. Error Code Handling & Localization

All 13 backend error codes are caught by `SaasStaffException` and translated into clear Spanish localized alerts:
- `UNAUTHORIZED_ROLE` $\rightarrow$ *"No tienes permisos suficientes..."*
- `SELF_ROLE_MUTATION_PROHIBITED` $\rightarrow$ *"Por motivos de seguridad y gobernanza, no puedes modificar tu propio rol."*
- `SELF_STATUS_MUTATION_PROHIBITED` $\rightarrow$ *"No puedes suspender ni revocar tu propia membresía."*
- `CANNOT_ORPHAN_ESTABLISHMENT` $\rightarrow$ *"Acción bloqueada: El establecimiento debe mantener al menos un (1) Propietario (Owner) activo."*
- `INVALID_STATE_TRANSITION` $\rightarrow$ *"Transición de estado inválida. Las membresías revocadas no pueden ser reactivadas."*
- `INVITATION_ALREADY_PENDING` $\rightarrow$ *"Ya existe una invitación pendiente para este correo electrónico en esta sede."*
- `USER_ALREADY_MEMBER` $\rightarrow$ *"Este usuario ya es un miembro activo o registrado de este establecimiento."*
- `INVITATION_EXPIRED` $\rightarrow$ *"Esta invitación ha expirado (+7 días transcurridos)..."*
- `INVITATION_REVOKED` $\rightarrow$ *"Esta invitación fue cancelada o revocada..."*
- `INVITATION_ALREADY_PROCESSED` $\rightarrow$ *"Esta invitación ya fue aceptada previamente."*
- `INVITATION_NOT_FOUND` $\rightarrow$ *"El enlace de invitación no es válido o no existe."*
- `IDENTITY_MISMATCH` $\rightarrow$ *"La cuenta actualmente autenticada no coincide con el correo destinatario..."*
- `TENANT_MISMATCH` $\rightarrow$ *"La cuenta pertenece a una organización distinta a la sede emisora."*
