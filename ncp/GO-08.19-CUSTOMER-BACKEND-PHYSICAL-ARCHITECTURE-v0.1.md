## 3. CONTROLADOR Y GOBIERNO DE ERRORES

### 3.1 Manejo Estandarizado de Respuestas de Error
Siguiendo la convención exacta de `nodo08TicketsController.js`:
```javascript
function handleControllerError(res, err) {
  const status = err.status || 500;
  const code = err.code || 'INTERNAL_SERVER_ERROR';
  return res.status(status).json({
    error: {
      code: code,
      message: err.message
    }
  });
}
```

### 3.2 Vocabulario de Errores Físicos Mapeados
| Código de Error | HTTP Status | Causa Fisiológica |
| :--- | :---: | :--- |
| `ACTIVE_CONTEXT_REQUIRED` | 403 | `req.activeContext` ausente o no resuelto. |
| `CUSTOMER_NOT_FOUND` | 404 | El cliente no existe en `saas_customers` bajo el `tenant_id` activo. |
| `CUSTOMER_RELATION_NOT_FOUND` | 404 | El cliente no posee relación con la sede activa en `saas_customer_establishments`. |
| `CUSTOMER_ALREADY_RELATED` | 409 | Intento de duplicar relación cliente-sede (`uq_customer_per_establishment`). |
| `POSSIBLE_DUPLICATE_FOUND` | 409 | Coincidencia de teléfono/email en tenant sin `confirm_duplicate: true`. |
| `INVALID_CUSTOMER_STATUS` | 400 | El `status` no pertenece al dominio (`ACTIVE`, `INACTIVE`, `ARCHIVED`). |
| `USER_NOT_FOUND` | 404 | El `user_id` suministrado no existe en `public.usuarios`. |
| `USER_CROSS_TENANT` | 403 | El `usuarios.tenant_id` difiere del `tenant_id` del contexto activo. |
| `USER_ALREADY_LINKED` | 409 | El cliente ya está vinculado o el usuario ya pertenece a otro cliente. |
| `FORBIDDEN_TENANT_SCOPE` | 403 | Rol operativo (`RECEPTIONIST`/`PROFESSIONAL`) solicitando `scope=tenant`. |
| `FORBIDDEN_ROLE` | 403 | Rol de la membresía activa no autorizado para la operación. |
| `UNAUTHORIZED_STATUS_CHANGE` | 403 | Rol `RECEPTIONIST` intentando mutar `status`. |
| `INVALID_SEARCH_QUERY` | 400 | Término de búsqueda con longitud inferior a 3 caracteres. |
| `INVALID_PAGINATION_PARAMS` | 400 | Parámetros `page` o `limit` fuera de rango. |

## 4. ESPECIFICACIÓN FÍSICA DE OPERACIONES Y SERVICIOS

### 4.1 `searchCustomers(activeContext, queryParams)`
- **Firma:** `async searchCustomers(activeContext, { q, limit })`
- **Validación:** `q` obligatorio, `q.trim().length >= 3`. Default `limit = 10`, max `limit = 30`.
- **Query SQL:**
  ```sql
  SELECT c.id, c.first_name, c.last_name, c.phone, c.email, c.birth_date, c.status,
         (c.user_id IS NOT NULL) AS is_linked_to_user,
         (ce.id IS NOT NULL) AS has_local_relation,
         ce.local_notes, ce.is_active AS is_active_in_establishment, ce.last_visited_at
  FROM saas_customers c
  LEFT JOIN saas_customer_establishments ce 
         ON ce.customer_id = c.id 
        AND ce.establishment_id = $2 
        AND ce.tenant_id = $1
  WHERE c.tenant_id = $1
    AND (c.phone ILIKE $3 OR c.first_name ILIKE $3 OR c.last_name ILIKE $3 OR c.email ILIKE $3)
  ORDER BY ce.last_visited_at DESC NULLS LAST, c.created_at DESC
  LIMIT $4;
  ```

### 4.2 `listCustomers(activeContext, queryParams)`
- **Firma:** `async listCustomers(activeContext, { scope, page, limit, status })`
- **Validación de Alcance:**
  - Si `scope === 'tenant'`: Verificar `activeContext.role IN ('OWNER', 'MANAGER')`. Si no cumple -> Throw `FORBIDDEN_TENANT_SCOPE` (403).
  - Si `scope === 'establishment'` (default): Accesible para todos los roles.
- **Paginación:** `limit = Math.min(parseInt(limit || 20), 50)`, `offset = (Math.max(parseInt(page || 1), 1) - 1) * limit`.
- **Query SQL (Scope Establishment):**
  ```sql
  SELECT c.id, c.first_name, c.last_name, c.phone, c.email, c.birth_date, c.status,
         (c.user_id IS NOT NULL) AS is_linked_to_user,
         ce.local_notes, ce.is_active AS is_active_in_establishment, 
         ce.first_visited_at, ce.last_visited_at, c.created_at
  FROM saas_customer_establishments ce
  JOIN saas_customers c ON c.id = ce.customer_id AND c.tenant_id = ce.tenant_id
  WHERE ce.tenant_id = $1 AND ce.establishment_id = $2
    AND ($3::varchar IS NULL OR c.status = $3)
  ORDER BY ce.last_visited_at DESC
  LIMIT $4 OFFSET $5;
  ```

### 4.3 `createCustomer(activeContext, payload)`
- **Firma:** `async createCustomer(activeContext, { first_name, last_name, phone, email, birth_date, local_notes, confirm_duplicate })`
- **RBAC:** `activeContext.role IN ('OWNER', 'MANAGER', 'RECEPTIONIST')`.
- **Frontera Transaccional:**
  ```javascript
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    await client.query("SELECT set_config('app.tenant_id', $1, true)", [activeContext.tenant_id.toString()]);
    
    // 1. Validar duplicados si confirm_duplicate !== true
    if (!confirm_duplicate) {
      const dupRes = await client.query(`
        SELECT id, first_name, last_name, phone, email FROM saas_customers 
        WHERE tenant_id = $1 AND (phone = $2 OR (email IS NOT NULL AND email = $3))
      `, [activeContext.tenant_id, sanitizedPhone, sanitizedEmail]);
      
      if (dupRes.rows.length > 0) {
        const err = new Error('Se detectaron posibles clientes duplicados en la organización.');
        err.status = 409;
        err.code = 'POSSIBLE_DUPLICATE_FOUND';
        err.candidates = dupRes.rows;
        throw err;
      }
    }
    
    // 2. Insertar saas_customers
    const custRes = await client.query(`
      INSERT INTO saas_customers (tenant_id, first_name, last_name, phone, email, birth_date, created_by_membership_id)
      VALUES ($1, $2, $3, $4, $5, $6, $7)
      RETURNING *;
    `, [activeContext.tenant_id, first_name.trim(), (last_name || '').trim(), sanitizedPhone, sanitizedEmail, birth_date || null, activeContext.active_membership_id]);
    
    const customer = custRes.rows[0];
    
    // 3. Insertar saas_customer_establishments
    const relRes = await client.query(`
      INSERT INTO saas_customer_establishments (tenant_id, customer_id, establishment_id, local_notes)
      VALUES ($1, $2, $3, $4)
      RETURNING *;
    `, [activeContext.tenant_id, customer.id, activeContext.establishment_id, local_notes || null]);
    
    await client.query('COMMIT');
    return { ...customer, establishment_relation: relRes.rows[0] };
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
  ```

### 4.4 `getCustomerById(activeContext, customerId)`
- **Validación Anti-IDOR:**
  ```sql
  SELECT c.*, (c.user_id IS NOT NULL) AS is_linked_to_user,
         ce.id AS relation_id, ce.local_notes, ce.is_active AS is_active_in_establishment,
         ce.first_visited_at, ce.last_visited_at
  FROM saas_customers c
  LEFT JOIN saas_customer_establishments ce 
         ON ce.customer_id = c.id 
        AND ce.establishment_id = $2 
        AND ce.tenant_id = $1
  WHERE c.id = $3 AND c.tenant_id = $1;
  ```
- Si `rows.length === 0` -> Throw `CUSTOMER_NOT_FOUND` (404).

### 4.5 `updateCustomer(activeContext, customerId, payload)` (Canónico)
- **Firma:** `async updateCustomer(activeContext, customerId, { first_name, last_name, phone, email, birth_date, status })`
- **RBAC:**
  - Si `status` está presente: `activeContext.role IN ('OWNER', 'MANAGER')`. Si `RECEPTIONIST` lo intenta -> Throw `UNAUTHORIZED_STATUS_CHANGE` (403).
  - Datos de contacto: `OWNER`, `MANAGER`, `RECEPTIONIST`.
- **Frontera Transaccional:** `BEGIN ... COMMIT` con `SET LOCAL "app.tenant_id" = $tenantId`.
- **Actualización:** `UPDATE saas_customers SET ... WHERE id = $customerId AND tenant_id = $tenantId`.

### 4.6 `createEstablishmentRelation(activeContext, customerId, { local_notes })`
- **RBAC:** `activeContext.role IN ('OWNER', 'MANAGER', 'RECEPTIONIST')`.
- **Frontera Transaccional:** `BEGIN ... COMMIT`.
- **Lógica:**
  1. Verifica existencia de cliente en `tenant_id`.
  2. Inserta en `saas_customer_establishments`. Si viola `uq_customer_per_establishment` -> Throw `CUSTOMER_ALREADY_RELATED` (409).

### 4.7 `updateCurrentEstablishmentRelation(activeContext, customerId, { local_notes, is_active })`
- **RBAC:**
  - `local_notes`: `OWNER`, `MANAGER`, `RECEPTIONIST`, `PROFESSIONAL`.
  - `is_active`: `OWNER`, `MANAGER`, `RECEPTIONIST`.
- **Actualización:** `UPDATE saas_customer_establishments SET ... WHERE customer_id = $customerId AND establishment_id = $establishmentId AND tenant_id = $tenantId`.

### 4.8 `linkUser(activeContext, customerId, { user_id })` & `unlinkUser(activeContext, customerId)`
- **RBAC:** `activeContext.role IN ('OWNER', 'MANAGER')`.
- **Link User:**
  1. Consulta `SELECT tenant_id FROM usuarios WHERE id = $user_id`. Si no existe -> Throw `USER_NOT_FOUND` (404).
  2. Verifica `usuarios.tenant_id === activeContext.tenant_id`. Si no coincide -> Throw `USER_CROSS_TENANT` (403).
  3. `UPDATE saas_customers SET user_id = $user_id, updated_at = CURRENT_TIMESTAMP WHERE id = $customerId AND tenant_id = $tenantId`.
- **Unlink User:**
  1. `UPDATE saas_customers SET user_id = NULL, updated_at = CURRENT_TIMESTAMP WHERE id = $customerId AND tenant_id = $tenantId`.

### 4.9 `getCustomerHistory(activeContext, customerId)` (Read-Only)
- **RBAC:** `OWNER`, `MANAGER`, `RECEPTIONIST`, `PROFESSIONAL`.
- **Lógica Fisiológica de Consulta:**
  1. Obtener cliente: `SELECT user_id FROM saas_customers WHERE id = $customerId AND tenant_id = $tenantId`.
  2. **Caso 1: `user_id` NO es nulo (`ATTRIBUTED_VIA_USER_ACCOUNT`):**
     ```sql
     -- Citas NODO-06
     SELECT id, establishment_id, service_name_snapshot, scheduled_at, status, price_snapshot 
     FROM saas_appointments 
     WHERE tenant_id = $1 AND customer_user_id = $2 
     ORDER BY scheduled_at DESC LIMIT 20;

     -- Tickets NODO-08
     SELECT id, folio, establishment_id, status, total_amount, created_at 
     FROM saas_service_tickets 
     WHERE tenant_id = $1 AND customer_user_id = $2 
     ORDER BY created_at DESC LIMIT 20;
     ```
  3. **Caso 2: `user_id` es nulo (`UNLINKED_NO_ATTRIBUTED_HISTORY`):**
     - Retorna `appointments: []`, `tickets: []`, `summary.total_spend = 0.00`.
     - **CERO inferencia por datos de contacto GUEST.**

## 5. MATRIZ FÍSICA DE RBAC

| Operación | OWNER | MANAGER | RECEPTIONIST | PROFESSIONAL | Justificación Arquitectónica |
| :--- | :---: | :---: | :---: | :---: | :--- |
| `SEARCH` | ALLOW | ALLOW | ALLOW | ALLOW | Consulta de directorio para agenda/caja/atención. |
| `LIST ESTABLISHMENT` | ALLOW | ALLOW | ALLOW | ALLOW | Vista de directorio de clientes de la sede. |
| `LIST TENANT` | ALLOW | ALLOW | DENY (403) | DENY (403) | Directorio corporativo multi-sede restringido a gestión. |
| `READ DETAIL` | ALLOW | ALLOW | ALLOW | ALLOW | Visualización de ficha y notas de atención. |
| `CREATE CUSTOMER` | ALLOW | ALLOW | ALLOW | DENY (403) | Registro en mostrador/caja. Profesional no administra directorio. |
| `EDIT CONTACT DATA` | ALLOW | ALLOW | ALLOW | DENY (403) | Actualización de teléfono/email en recepción. |
| `EDIT STATUS` | ALLOW | ALLOW | DENY (403) | DENY (403) | Inactivación/archivo es decisión administrativa. |
| `EDIT LOCAL NOTES` | ALLOW | ALLOW | ALLOW | ALLOW | Registro de fórmulas técnicas y preferencias por el profesional. |
| `EDIT RELATION ACTIVE`| ALLOW | ALLOW | ALLOW | DENY (403) | Estado de pertenencia a la sede. |
| `LINK ESTABLISHMENT` | ALLOW | ALLOW | ALLOW | DENY (403) | Afiliación de cliente a nueva sucursal. |
| `LINK USER` | ALLOW | ALLOW | DENY (403) | DENY (403) | Gobierno de identidad global B2C. |
| `UNLINK USER` | ALLOW | ALLOW | DENY (403) | DENY (403) | Gobierno de identidad global B2C. |
