# D002.1-UX-SPEC.md

## UX Specification for Workforce Management (D-002)

**Note**: This is a conceptual UX specification only. No implementation is authorized at this stage.

### Overview
This specification describes the user interface concepts for allowing salon owners/administrators to manage the operational classification of their workforce members (e.g., marking a user as EMPLEADO or PRESTADOR_SERVICIO) within the GlowApp SaaS.

### Core Principles
- The UI must clearly communicate that the classification is **operational only** and does not determine legal relationships.
- All workforce management features must be scoped to the current tenant (salon).
- The UI should use language that emphasizes salon control (e.g., "Tu equipo", "Gestión de tu personal").
- Avoid any terminology that could imply GlowApp is the employer (e.g., "Nuestro equipo", "Empleados de GlowApp").
- The design should be consistent with the existing GlowApp design system and accessibility guidelines.

### User Flow: Managing Workforce Classification

#### Entry Point
- From the salon dashboard, a navigation item labeled **"Equipo"** or **"Personal"** leads to the workforce management section.
- This section is only visible to users with appropriate permissions (e.g., salon admin, owner).

#### Workforce List View
- Displays a table or cards of workforce members (users) belonging to the salon.
- Each item shows:
  - Foto de perfil (if available)
  - Nombre completo
  - Correo electrónico
  - Rol de inicio de sesión (CLIENTE / PRESTADOR) – small badge
  - **Categoría operativa** (dropdown or badge showing: EMPLEADO, PRESTADOR_SERVICIO, ADMIN_SALON, OTRO, or blank if not set)
  - Estado activo/inactivo (toggle)
  - Acciones: Editar categoría, Ver perfil, Desactivar (if applicable)
- Controls:
  - Barra de búsqueda por nombre o correo
  - Filtro por categoría operativa (multiple select)
  - Filtro por estado (Activo, Inactivo, Todos)
  - Botón "Invitar a miembro del equipo" (to add a new user or send an invitation)

#### Edit Workforce Member Modal
- Triggered by clicking "Editar categoría" on a workforce member.
- Fields:
  - Nombre (read-only)
  - Correo (read-only)
  - Rol de inicio de sesión (read-only, info only)
  - **Categoría operativa** (required dropdown with options: EMPLEADO, PRESTADOR_SERVICIO, ADMIN_SALON, OTRO)
  - Estado activo/inactivo (toggle)
- Help text below the categorical dropdown:
  > "Esta clasificación es exclusivamente para uso operativo dentro de tu salón. No determina la naturaleza jurídica de la relación entre la persona y tu establecimiento, ni crea ninguna obligación para GlowApp."
- Buttons: Cancelar, Guardar cambios

#### Empty State
- If no workforce members have been added yet:
  - Illustration or icon of a team
  - Text: "Aún no has agregado miembros a tu equipo. Invita a tu personal o profesional para comenzar."
  - Botón: "Invitar al equipo"

### Accessibility Considerations
- Ensure sufficient color contrast for badges and text.
- All interactive elements must be keyboard accessible.
- Use ARIA labels where necessary (e.g., for status toggles).
- Provide clear error messages and validation.

### Risks and Mitigations
| Risk | Mitigation |
|------|------------|
| Users may confuse operational category with legal relationship | Include help text and tooltips that clarify the purpose is strictly operational. Avoid legal terms in UI. |
| Inconsistent terminology across the platform | Centralize strings in a localization file; use same terms throughout (e.g., always "Categoría operativa"). |
| Accidental exposure of workforce data to wrong tenant | Ensure backend enforces tenant isolation; UI should not show data from other tenants. RLS and middleware must be verified. |
| Overwhelming UI for salons with many members | Implement pagination, infinite scroll, or virtual scrolling for large lists. |

### Components to be Created (Conceptual)
- WorkforceListPage
- WorkforceTable / WorkforceCard
- WorkforceFilterBar
- WorkforceSearchBox
- EditWorkforceModal
- InviteWorkforceMemberModal (if not already existing)

### Style Guidelines
- Use existing GlowApp color palette and typography.
- Badges for categorical values: use subtle background colors (e.g., blue for PRESTADOR_SERVICIO, green for EMPLEADO, gray for OTRO).
- Avoid using red or warning colors unless indicating an error state.
- Follow existing spacing and layout conventions.
