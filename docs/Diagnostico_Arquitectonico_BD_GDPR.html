1. Resumen Ejecutivo

Este documento presenta el diagnóstico arquitectónico del módulo de biometría y belleza de Belleza App, centrado en el mapa de dependencias implícitas, la reconstrucción del esquema de base de datos desde el código existente, la identificación de índices faltantes, el análisis de campos sensibles bajo GDPR (Art. 9) y Ley 1581 Colombia, y un resumen de riesgos críticos de severidad alta.

Contexto: El diagnóstico se realiza mediante ingeniería inversa sobre código de rutas (biometricScanRoutes, vtoRoutes, authMiddleware) y consultas SQL embebidas. Se detectan violaciones bloqueantes de cumplimiento legal (GDPR Art. 6, 7, 9, 25, 32; Ley 1581 Art. 5, 9, 15) que impiden el despliegue en producción sin remediación inmediata.

Objetivo: Proporcionar una especificación técnica accionable para generar migraciones de base de datos, refactorización de servicios y controles de seguridad que elevan el módulo a un estándar empresarial de privacy by design.

3. Esquema DB Reconstruido — Tabla user_biometrics

Columna Tipo Inferido Nulable Sensible GDPR / Ley 1581 Observación / Violación
id SERIAL / BIGSERIAL NO No PK implícita en tabla
user_id VARCHAR / UUID NO SÍ Inconsistencia de tipo: 'guest' string vs ID numérico/UUID
subtono VARCHAR(50) SÍ SÍ Dato biométrico derivado (cálido, frío, neutro, oliva)
paleta JSONB SÍ SÍ Actualmente stringificado como TEXT → Debe ser JSONB nativo
hidratacion SMALLINT SÍ SÍ Escala biométrica de piel (0-100%)
sebo SMALLINT SÍ SÍ Escala biométrica de piel (0-100%)
consent_id BIGINT NO SÍ 🚨 NO EXISTE EN CÓDIGO ACTUAL — FK a biometric_consents.id requerida
created_at TIMESTAMPTZ NO No 🚨 FALTA EN INSERT ACTUAL — Imposibilita auditoría temporal (GDPR Art. 17)

4. Esquema DB Reconstruido — Tabla biometric_consents

Columna Tipo Inferido Sensible Violación Detectada
user_id BIGINT SÍ Sin FOREIGN KEY explícita con CASCADE en tabla users.
ip INET / VARCHAR SÍ Almacenado en texto plano → Violación de minimización y cifrado (Art. 32).
user_agent TEXT SÍ Huella digital del dispositivo expuesta en texto plano.
active BOOLEAN No Falta índice único parcial UNIQUE(user_id) WHERE active = true. Permite race conditions.

5. Índices Faltantes Requeridos

Tabla Índice Requerido Tipo Query Afectada / Justificación

6. Campos Sensibles & Estrategia de Cifrado (pgcrypto)

Bajo el GDPR (Art. 9) y la Ley 1581 de Colombia (Art. 5), los datos derivados del análisis de piel y rostro son categorías especiales de datos biológicos/sensibles.

  • Cifrado en reposo: Aplicar pgcrypto con claves gestionadas en AWS KMS / HashiCorp Vault.
  • Campos a cifrar: subtono, estacion, paleta, hidratacion, sebo, mensaje_aura, así como la ip y el user_agent del consentimiento.
  • Vistas Seguras: Creación de vistas SECURITY DEFINER para la desencriptación controlada en tiempo de ejecución.

7. Resumen de Riesgos Críticos (Severidad Alta)

# Riesgo Impacto Mitigación Inmediata
1 Sin consent_id en user_biometrics Ilegalidad del procesamiento (multas hasta 4% facturación global GDPR). Migración 024 para vincular obligatoriamente el consent_id.
2 IP y User-Agent en texto plano Exposición de metadatos de localización y huella digital. Aplicar cifrado simétrico mediante pgp_sym_encrypt.
3 Race condition en consentimiento Múltiples consentimientos activos en paralelo. Índice único parcial uq_bc_user_active.
4 user_id tipo mixto ('guest' vs UUID) Imposibilidad de aplicar Integrity Constraints (FKs). Migrar a UUID y canalizar guests mediante tabla anonymous_sessions.
