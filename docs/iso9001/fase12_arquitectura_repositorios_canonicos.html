1. Declaración Oficial de Repositorios Canónicos (Cláusulas 7.5.3 & 8.5.6)

Para eliminar cualquier ambigüedad en la gestión del código fuente de **GlowApp S.A.S.**, el presente documento declara de manera vinculante la responsabilidad operacional y el alcance de cada uno de los repositorios del sistema:

Directorio / Repositorio Tecnología Base Rol Canónico Oficial de Producción Target CI/CD & Deploy
/frontend React.js / Node / Docker Web Portal Web Oficial de Producción (Web Client & Admin Dashboard). Atiende navegación web, marcas e interfaz administrativa. Docker Hub → AWS ECS / Railway Web Service (docker-compose.prod.yml)
/glowapp_frontend Flutter Cross-Platform (Dart) Aplicación Móvil Nativa de Producción (iOS & Android). Atiende a usuarios finales y prestadores independientes en smartphones. App Store Connect (iOS) / Google Play Console (Android APK/AAB)
/backend Node.js / Express / PostgreSQL API Server Central, Hub Biométrico y Motor de IA. Procesa autenticación facial, pasarelas de pago y reservas. Docker Hub → Production Cloud API Cluster (docker-compose.prod.yml)

2. Flujo Canónico de Control de Cambios y Pipeline CI/CD

Cualquier modificación en los repositorios de produccion debe cumplir estrictamente la ruta de aprobación sin excepciones:

Ruta Obligatoria de Despliegue a Producción

1. Desarrollo Local: Creación de rama de característica (feature/nombre-cambio).
2. Pull Request (PR): Apertura de PR hacia la rama staging con revisión de código por pares.
3. Pruebas QA Automatizadas: Ejecución de la suite de pruebas unitarias e integración en Staging (0 bugs bloqueantes).
4. Aprobación CTO: Firma digital y autorización del CTO en el Pull Request.
5. CI/CD Deploy: Integración continua hacia la rama main y despliegue automático a producción.
6. Garantía de Rollback: Monitoreo automático en 5 minutos post-despliegue con reversión instantánea ante anomalías.
