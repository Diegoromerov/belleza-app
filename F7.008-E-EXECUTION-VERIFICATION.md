# F7.008-E — Execution / Verification

## Objective
Execute the implementation of traceId propagation, fallback utilization, and timeout consistency for YouCam and Gemini clients as per the design decisions in F7.008-D.

## Scope
- Implement traceId propagation in YouCamClient and GeminiClient.
- Implement fallback utilization in YouCamClient and GeminiClient.
- Adjust timeout consistency: use resilience policy default timeout (5000ms) for resilience layer, keep axios timeout at 15000ms.
- Update integration tests to verify the new behavior.
- Ensure no regression in existing functionality.

## Activities Performed

### 1. TraceId Propagation
- Modified `YouCamClient.analyzeFace` to accept an optional `traceId` parameter and pass it to each `executeWithResilience` call.
- Modified `GeminiClient.analyzeHands` and `GeminiClient.generateRecommendation` to accept an optional `traceId` parameter and pass it to the respective `executeWithResilience` calls.
- Updated the BiometricOrchestrator to pass the traceId from the request context (if available) to the client methods.

### 2. Fallback Utilization
- Added fallback functions for each step in YouCamClient:
  - `_requestUploadSlotFallback`
  - `_uploadToS3Fallback`
  - `_createAnalysisTaskFallback`
  - `_pollTaskResultFallback`
- Updated each `executeWithResilience` call in YouCamClient to include the `fallback` option pointing to the respective fallback function.
- In GeminiClient, updated the `executeWithResilience` calls in `analyzeHands` and `generateRecommendation` to include the `fallback` option pointing to `getFallbackHandsDiagnosis` and `getFallbackRecommendation` respectively.
- Kept existing try-catch blocks as a last resort for errors not covered by the resilience layer (e.g., parsing errors).

### 3. Timeout Consistency
- Removed the `timeout: this.timeout` option from the `executeWithResilience` calls in YouCamClient and GeminiClient, allowing the resilience service to use the default policy timeout of 5000ms per attempt.
- Kept the axios timeout as `timeout: this.timeout` (15000ms) in the axios config for each HTTP request.
- This configuration ensures that the resilience layer times out after 5000ms (triggering retries) while the HTTP request can take up to 15000ms before failing.

### 4. Test Updates
- Updated `backend/src/tests/youcam.client.integration.test.js` to match the new fallback return structures and added a timeout for the polling test.
- Verified that all YouCam integration tests pass.
- Verified that the frontend tests (flutter) pass.
