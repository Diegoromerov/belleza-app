## 3. H4 — Cascadas
### Contexto
Se verificó la existencia de foreign keys con `ON DELETE CASCADE` en migraciones:
- `020_biometric_consent_and_profiles.sql`: `beauty_profiles(user_id)` y `biometric_consents(user_id)` reference `usuarios(id) ON DELETE CASCADE`.
### Hecho verificable
Las cascadas eliminan automáticamente filas hijas si se elimina la fila de usuario. Actualmente, el flujo `deleteAccount` no elimina la fila de `usuarios` (solo anonimiza campos), por lo que las cascadas no se activan.
### Riesgo
- Si se decide eliminar físicamente usuarios en el futuro, las cascadas podrían eliminar datos esperados (perfiles, consentimientos) o datos transaccionales si se extienden a otras tablas.
- Mantenerlas implica depender de la eliminación física de usuarios para limpiar datos hijas; si no se elimina el usuario, los hijas persisten.
### Alternativas
- **H4-A — MANTENER**: Conservar las cascadas actuales. No requeriría cambio de código o esquema.
- **H4-B — REVISAR SELECTIVAMENTE**: Evaluar si ciertas relaciones deberían tener comportamiento distinto (por ejemplo, `SET NULL` o `NO ACTION`). Requeriría análisis caso por caso.
- **H4-C — ELIMINAR/MODIFICAR CASCADAS**: Cambiar a `NO ACTION` o eliminar la foreign key. Requeriría migración y revisión de dependencias.
### Consecuencia técnica
- **H4-A**: Ningún cambio.
- **H4-B**: Requeriría crear nuevas migraciones para alterar el comportamiento de foreign keys en tablas específicas.
- **H4-C**: Requeriría migraciones para dropear o modificar foreign keys, y posible actualización de lógica de eliminación si se espera que se eliminen hijas.
