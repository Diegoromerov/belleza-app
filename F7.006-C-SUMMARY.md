✅ Circuit Breaker: Available service with states (CLOSED, OPEN, HALF-OPEN), failure threshold (default 5), cooldown period (default 30000ms), and reset.
✅ Fallback: Supported by the resilience service (optional fallback function).
✅ TraceId: Integrated for logging resilience events (attempts, timeouts, failures, circuit breaker state changes).
✅ Centralized Policy: Default policies defined in a separate module (resiliencePolicy.js) for consistency.

## Design Details (to be implemented)
1. **Resilience Service Enhancement** (`backend/src/services/resilienceService.js`):
   - Add default policy export.
   - Accept optional `traceId` in options and log it with resilience events.
   - Enhance logging to include attempt counts, timeouts, failures, and circuit breaker state changes.
   - Ensure backward compatibility (existing callers without traceId still work).

2. **Centralized Policy Module** (`backend/src/services/resiliencePolicy.js`):
   - Export default values:
     * retry: 3
     * retryDelay: 100 (base for exponential backoff)
     * timeout: 5000 (per attempt timeout in ms)
     * circuitBreakerFailureThreshold: 5
     * circuitBreakerTimeout: 30000 (recovery timeout in ms)
   - These values are starting points and subject to validation via testing.

3. **External Service Clients Update** (YouCamClient and GeminiClient):
   - Remove hardcoded resilience options (retry, retryDelay, timeout) and import default policy.
   - Pass `circuitBreakerName` ('youcam' for YouCamClient, 'gemini' for GeminiClient) to enable circuit breaker protection.
   - Optionally pass a `fallback` function (though clients have internal fallback, the resilience service's fallback can be used for a more centralized approach).
   - Ensure traceId is propagated (if available from middleware) to the resilience service for logging.
